# 自然言語シナリオの実行手順

受入確認、探索、再現調査で使う。繰り返し検出したい回帰が見つかった場合は、同じ期待値と観測点を使ってPlaywright Testのspecへ移す。

## ケースを準備する

環境・アカウント・役割、操作前のデータ、操作列、比較する期待値とその出典、観測点、後処理を試行前にそろえる。条件の組み合わせが重要なときは因子と水準を決定表にして、各ケースで検証する列を明示する。計算結果は事前に得た仕様例や独立した参照値と照合できるようにする。

| 項目 | 例 |
| --- | --- |
| 対象 | ステージングの視聴画面、専用のテストアカウント |
| 前提 | 作品Aが配信中で、お気に入りに未登録。検証するFeature flagの値を固定する |
| 操作 | 作品Aの詳細からお気に入りに追加し、一覧を開く。一覧を再読み込みする |
| 期待結果・根拠 | 作品Aが一覧に1件表示され、再読み込み後も残る。保存仕様に基づく |
| 観測と後処理 | 再読み込み後に作品Aの行と件数を確認し、追加した作品Aだけ解除する |

## 操作して判定する

1. 利用できるPlaywright CLI、ブラウザツール、既存の操作リファレンスを確認する。Playwright CLIを使う場合は導入済みの版のヘルプを確認する。Playwright Testの `playwright test` は既存specの実行に使う。
2. ケースごとに独立したセッションやコンテキストを使う。操作前には現在の画面から対象を特定し、遷移やダイアログで画面が変わったらスナップショットを取り直す。スナップショットの参照IDはそのセッションの最新状態に従う。対象を特定できない場合は、画面と該当ステップを記録して判定を保留する。
3. 手順にある操作を実行し、予定した観測点で期待値と照合する。予定外の操作が調査に必要なら、その操作と観測を記録する。ケースの前提や判定基準を変更する場合は、変更したケースとして実行する。
4. ケースごとに成功・失敗・ブロックを記録し、期待値、観測値、異常が起きたステップ、スクリーンショットやtraceなどの根拠を紐付ける。環境起動やログインで止まった場合はブロックとして扱う。証跡の共有先と認証情報・個人情報の取り扱いはプロジェクトの運用に従う。
5. 操作手順を繰り返し使う場合は、確認済みの前提・操作・完了条件を短いリファレンスに残す。ケース固有の期待値は各ケースに保持する。
