# 要求獲得・仕様化・評価

参照章は「本書の使い方」「実プロジェクトでのテーラリング」、第 1〜3 章、第 7 章、第 8 章 8.1〜8.3 節・8.5〜8.6 節。

## 目的・制約と要望を具体化する

誰の何が改善するのか、現状を示す事例や値、どの観測で成功と判断するかを記録する。提案された機能や技術は、目的を満たす手段の候補として扱う。現行の手順・承認・帳票・データ項目は、義務の根拠と業務上の目的を確認する。判断や手順を簡素化できるかを検討し、必要な判断は担当、判断基準、例外時の扱いを明確にする。

## 聞き取りと根拠の集め方

| 知りたいこと | 確かめ方 |
| --- | --- |
| 目的・判断基準 | 責任者に、変えたい結果、現状の値や事例、成功と判断する条件、優先する価値を聞く。 |
| 日常の流れと例外 | 現場に直近の具体例を再現してもらう。開始から完了まで誰が何を見て判断するか、回避策、引き継ぎ、失敗時の復旧を観察する。 |
| 組織間の認識差 | 関係者と同じ事例をたどり、入力の意味、責任の切り替わり、承認の順序、運用時の連絡先を比較する。 |
| 規模・発生頻度 | 問い合わせ、障害、操作ログ、監査指摘などの出所・期間・件数を記録する。多数の傾向と、頻度が低くても被害や価値が大きい事象を調べる。後者は原典でいう「光る原石」。該当する事例の根拠を添え、現場・専門家と深掘りする。 |
| 利用時の理解や期待 | 試作品や画面案を使い、利用者が前提を理解できるか、手順を完了できるかを確かめる。 |

手段として語られた要望には、「最近それが必要だった場面は何か」「手段を使えないと何が困るか」「その結果を得られれば、どの手順を省けるか」と聞く。関係者の発言、観察結果、推測は区別し、同意や仕様を判断できる発生源を残す。誰が・いつ・どこで・何を・なぜ・どのように行うかを押さえ、実際の開始条件、終点、制約を確認する。答えによって対象範囲や受入条件が変わる質問を優先する。

## 分析と優先順位

- 要求ごとに、上位の目的、対象の人・業務、必要とする理由、発生源、変えられない制約を示す。慣習や既存手順は、根拠と目的を確かめて簡素化できるかを検討する。
- 成果と手段、事業・利用者・システム・ソフトウェアの階層を切り分け、重複はまとめ、対立は両方の根拠を残す。機能・品質・データ・ルール・運用・評価の観点は、関係する要件の抜けを探すために使う。
- 競合や依存がある場合は、可能な選択肢と、それぞれで満たす条件・保留になる条件・導入と運用の負担を示す。人の手順、権限・ルール、データ整備、既存機能、追加開発を比較対象に含める。優先度には、義務、影響の大きさ、他の要求の前提となるか、実現の負担など、判断に使った根拠を添える。

## 要件と受入条件を書く

- 一つの要件には、主に一つの振る舞いまたは品質を記す。**成立条件 → 対象が行うこと → 観測できる結果**を基本に、入力・出力、権限、失敗時の扱いを必要に応じて添える。
- 性能・品質は対象操作、負荷やデータの条件、測定点、指標、しきい値をそろえる。どの利用環境・利用者群・対象期間に適用するかで結果が変わる場合は特定する。基準値が未決なら、測定できるところまで記述し、決定に必要な根拠と責任者を示す。
- 受入条件は、前提、操作または変化、期待結果をそろえる。境界値、データ不足、権限外、外部依存の失敗、手動運用など、要件の解釈や結果に影響する場合を選ぶ。評価がテスト以外なら、観察、レビュー、監査、シミュレーションなどの方法と確認する証拠を示す。
- 例として「処理を速くする」を「確定済みの月次売上を会計担当者が画面から出力できる」と「最大対象件数の条件で出力完了までの時間が合意値以内になる」に分ける。最大件数・時間の合意がなければ、測定条件とともに未決事項にする。

## レビューで確かめる

| 観点 | 確認内容 |
| --- | --- |
| 要件文の品質 | 必要性、意味の一意性、記述の粒度、実現可能性、検証可能性、出典との対応。 |
| 要件集合の品質 | シナリオを通した抜け、用語やデータ定義の矛盾、依存関係、制約、運用上の受け渡し。 |
| 妥当性確認 | 業務シナリオを関係者とたどり、要件が満たされた場合に期待する価値が得られるか確かめる。 |
| 実現後の検証 | 運用条件、テストデータ、期待結果、測定方法をそろえ、設計や実装が合意した要件を満たすか確認する。 |

妥当性確認では、同じシナリオで関係者が目的・優先度・制約とそれぞれの役割を同じように理解しているかを見る。実装後の検証では、合意した条件を満たした観測結果を残す。

指摘は「対象 ID・箇所 → 確認した根拠 → 放置した場合の影響 → 修正案または質問」の形で書く。個別の条件を満たしても目的を達成できない場合は、関係者と目的・要求に戻る。
