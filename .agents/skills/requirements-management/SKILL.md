# 要求管理

目的と成功基準を起点に、**要望**（関係者の困りごと・期待）、**要求**（実現したいこと）、**要件**（実現すべき検証可能な条件）を具体化する。各要件から発生源と上位目的に戻れ、実現箇所、受入条件、検証結果へ進めるようにする。

## 作業の進め方

要求工学の基本活動は、獲得・分析・仕様化・評価・管理。この活動を構想から運用・廃止へつなぐ [12工程](references/lifecycle.md) を使い、現在の工程と、手戻りが必要な場合の戻り先を確認する。

1. **目的と責任を確かめる。** 誰のどの課題を解決するか、何を成功と判断するか、対象範囲と制約、影響を受ける人と判断する人を確認する。Issue、既存仕様、規則、業務記録などを調べ、根拠がある事実、合意内容、仮説を区別する。
2. **要求を獲得・分析する。** 通常の流れ、例外、少数でも影響が大きい事象を確認する。目的と提案された手段を分けて、必要性、既存業務の簡素化、代替手段、重複・矛盾・依存関係、優先度を検討する。
3. **要件を仕様化・可視化する。** 対象、成立条件、観測できる期待結果を、独立に検証できる粒度で記述する。受入条件と確認方法を結びつける。解釈が割れる箇所は、業務フロー、状態遷移、決定表、データ定義などを使う。
4. **評価し、合意を記録する。** 要件の品質と、業務上の目的を満たせるかを確かめる。根拠と受入条件に照らし、未決事項は判断する人と影響範囲を示す。設計・実装・調達の前提として合意した内容は、参照できる版を特定する。
5. **実現・運用・変更につなげる。** 既存の正本を使い、要件と実装・調達、運用手順、テスト・監査の証拠を結ぶ。フィードバックや条件の変化があれば影響をたどり、必要な工程へ戻る。移行・廃止も該当する場合は要件化する。

活動の深さは、影響、変更頻度、責任分界、監査の必要性に合わせる。小さな依頼は、目的・制約・受入条件・未決事項を既存の Issue や仕様にまとめればよい。数値や判断を仮置きした場合は区別し、承認済み・検証済みという状態は証拠に従って記録する。レビュー結果は、各指摘に該当箇所、影響、必要な判断または修正を添える。
