# 薬局システムのドメイン一覧

レセコン・電子薬歴の一体型クラウドシステムにおけるドメイン一覧と各コンテキストの責務・境界を定義する。両者は同一システム内の業務上の機能区分として整理し、内部では情報を直接共有する。

対象範囲は薬局業務全体（組織・施設基準、マスタ参照、患者・受給資格、処方・調剤、服薬指導・薬歴・フォローアップ・医療安全、在宅医療、調剤報酬算定・窓口会計・保険請求、調達・在庫・物販）とする。給与計算、人事評価、企業の財務会計は対象外とし、外部システムへ委ねる。

業務の流れは **レセコン入力 → 処方監査 → 調剤・鑑査 → 服薬指導・会計 → 薬歴記載 → フォローアップ** を軸とする。工程間の受け渡しと法定ゲートは [業務フロー](workflow.md) を参照。

## 1. 組織・基盤

文書: [組織・基盤](01-organization/README.md)

| ドメイン | 主な責務 | 境界の原則 |
| --- | --- | --- |
| 法人・法人間関係 (`corporate`) | 法人（区分：法人/個人、持株会社・個人開設者を含む）の識別、親子（支配）・関連会社・FC/VC契約と履歴 | 1法人＝1テナント。独立した企業グループ階層は設けず、報酬上の同一グループ判定結果と区別する |
| 店舗 (`store`) | 店舗、物理拠点（緯度経度・設備含む）、屋号、営業日時・休日輪番・連絡先、開設者関係、営業状態、薬局開設許可・麻薬小売業免許・保険薬局指定（承継系譜含）の履歴 | 店舗IDと所在地・許可番号・保険薬局コードを分離し、麻薬免許期限切れ時の麻薬調剤をブロックする |
| スタッフ (`staff`) | スタッフ（1アカウント＝1スタッフ）、保険薬剤師登録番号・資格、契約区分（雇用・派遣・委託）、店舗配属、勤務予定・実績、管理薬剤師の就任・専任要件 | 管理薬剤師の他店舗兼務を禁止し、常勤換算は店舗別・期間別の勤務実績から算出する |
| 施設基準・届出 (`facility_compliance`) | 届出、適用期間、根拠実績、外部実績サマリー、報酬上のグループ判定 (`GroupAssessment`)、R8基本料連動制約、地域支援加算維持要件、年次報告 | 報酬計算へ渡す調剤日時点の有効基準一覧と、元実績の正本を分離する |
| テナント・アクセス管理 (`tenant_access`) | 法人単位のデータ分離（1法人＝1テナント）、アカウント・RBAC認可（Role＋範囲＋期間）、M&Aデータ承継・移行、開設者別設定 | 店舗配属とアクセス権限を完全分離し、事業譲渡前のレセプト・調剤実績に対する新法人の遡及修正を禁止する |

## 4. 処方・調剤

文書: [処方・調剤](04-prescription-dispensing/README.md)

| ドメイン | 主な責務 | 境界の原則 |
| --- | --- | --- |
| 受付・処方入力 (`reception_entry`) | 一体型の患者登録・処方入力、紙/QR/電子処方箋/NSIPS取込、受入禁止処方箋のブロック、使用期間確認、同時受付・分割/リフィル識別 | 内部では情報を直接共有し、受入禁止処方箋や使用期間超過の保険調剤確定を阻止する |
| 処方箋・処方内容 (`prescription`) | 原記載、発行情報、患者・処方医、Rp、薬剤明細、用法・用量・単位・日数、変更不可・選定療養・リフィル指示、媒体固有情報 | 発行時の原記載、疑義照会後の確定指示、実際の調剤実績を分離して保持する |
| 処方監査・疑義照会 (`prescription_review`) | 保険薬剤師による取りそろえ前確認、形式・薬学的監査、電子処方箋重複チェック証跡、疑義照会完了ゲート、残薬調整・有害事象防止の根拠 | 疑義検知時は照会完了まで調剤確定をブロックし、処方変更時は原記載を上書きせず変更経緯を記録する |
| 調剤・鑑査 (`dispensing`) | 具体的製品選択、変更調剤（含量規格・類似別剤形変更4要件）、調剤手技・規制薬品・供給不安対応記録、最終鑑査、調剤録（保険/自費分離・追記型訂正履歴） | 無資格調剤・代筆署名を禁止し、確定実績から在庫払出および算定・調剤録へ連携する |

## 5. 服薬指導・薬歴・継続ケア

文書: [服薬指導・薬歴・継続ケア](05-pharmaceutical-care/README.md)

| ドメイン | 主な責務 | 境界の原則 |
| --- | --- | --- |
| 受付・相談・フォローアップのイベント (`care_event`) | 処方箋受付、来局・電話・OTC相談、フォローアップ等の出来事、開設者独自種別、イベント間関連、薬歴確定に伴うイベント完了 | 登録済み患者を必須入口とし、イベント先行作成と薬歴記載（確定後は追記）の紐づけを管理する |
| 服薬指導・交付 (`medication_counseling`) | 対面/オンライン/訪問指導、薬剤情報提供文書（無関係事項記載禁止）、お薬手帳（JAHIS出力制約含）、かかりつけ・特定指導、薬剤交付記録 | 指導実施日時と薬歴記載日時を分離し、医薬品提供を伴わない場合のJAHIS処方レコード出力を禁止する |
| 薬歴記載 (`medication_history`) | SOAP・法定確認事項（残薬なし明記必須等）、下書き・保険薬剤師確定（イベント完了・不足事項注意喚起）・複数者記載時の確定薬歴への追記・二本線抹消相当の訂正履歴、患者頭書きへの追記連動、最終記入日起算の全記録保持 | 未確定・代行入力状態での報酬確定・レセプト請求を禁止し、他店舗からは閲覧のみ・追記訂正は記録元店舗に限定する |
| フォローアップ (`follow_up`) | フォローアップ計画、双方向連絡・服薬状況確認（一斉メールのみ登録禁止）、評価・処方医情報提供、同一テナント内他店舗への引継ぎ | 元の薬歴への追記ではなく独立した実施記録として作成し、元の薬歴・イベントへ関連づける |
| 品質・インシデント (`quality`) | 薬局ヒヤリ・ハット事例収集・分析事業ベースの起票・提出、調査・是正措置・効果確認 | 発生源は臨床記録に紐づき、管理主体と閲覧境界は発生店舗の開設法人テナントに従う |

## 7. 算定・会計・請求

文書: [算定・会計・請求](07-reimbursement-billing/README.md)

| ドメイン | 主な責務 | 境界の原則 |
| --- | --- | --- |
| 算定 (`reimbursement`) | 処方・調剤・指導実績と施設基準に基づく無状態（Stateless）な点数計算、調剤基本料3段階、時間外基礎額、内服7種類減算、表1マトリクス検証、摘要コメント（`TK`）自動生成 | 状態を持たない純粋計算とし、臨床記録の直接書き換えや薬歴未承認時の確定を禁止する |
| 窓口会計 (`payment`) | 一部負担金計算（10円未満四捨五入）、公費上限・選定療養・自費項目の合算、領収証・明細書（無償交付原則）、入金・返金・未収管理 | 算定結果と実際の入出金・未収債権を分離して追跡する |
| 保険等の請求 (`billing_claim`) | 月次レセプト集約（`MonthlyReceipt` / `MN`）、薬歴承認・調剤録確定ゲート、同月内資格変更・分割調剤時のレコード分離、電算出力、返戻（`HR`）再請求、三者突合チェック | 提出時の原本スナップショットを不変保持し、処方箋・調剤録・レセプトの三者不一致時は請求出力をブロックする |

## レイヤーをまたぐ外部連携

NSIPSは外部連携用とし、一体型内部では情報を直接共有する。外部レセコン等の取込と、レセコン機能から他社の分包機等への送信を扱う。製品ごとの変換・送受信の責務と、患者・処方・調剤等の業務ルールを分離する。詳細は [一体型内部と外部連携の境界](external-integration.md) を参照。
