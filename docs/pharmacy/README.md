# 薬局ドメインの整理

想定する利用先はレセコン・電子薬歴の一体型クラウドシステム。レセコンと薬歴は業務上の責務として分け、再利用できるモデルを設計する。内部では患者・処方等を直接共有する。NSIPSは外部連携用とし、レセコン機能から他社の分包機等への連携も対象にする。詳細は [内部と外部連携の境界](external-integration.md) を参照。

法人開設・個人開設の薬局を対象とする。法人＝テナントとし、個人開設者も一開設者一テナントで管理する。インシデント・ヒヤリハットは店舗から起票し、その開設者が管理する。

目的は、業務ルールをコードで表現し、薬歴などの複数アプリから再利用できる薬局ドメインモデルを作ること。文書では、そのための用語・責務・ルール・境界を整理する。

将来の対象は薬局業務全体とし、在宅、算定・会計・請求、調達・在庫、薬局で販売する商品全般を含める。スタッフの資格・配属・勤務は対象とし、給与・人事評価・企業の財務会計は外部に任せる。最初に実装する範囲・順序は別途決める。

まず [ドメイン候補一覧](domain-candidates.md) から対象業務と責務を相談する。レイヤーは文書の分類であり、実装の依存方向を確定するものではない。

| [02 マスタ・外部参照](02-reference/README.md) | 医薬品情報、医療機関・外部関係者 |
| [03 患者・臨床・ケア](03-clinical/README.md) | レセコン入力、患者、資格、処方箋、監査、調剤、指導、在宅、薬歴、フォローアップ |
| [04 算定・会計・請求](04-business/README.md) | 算定、会計、請求 |

業務は [レセコン入力 → 服薬指導 → 薬歴記載 → フォローアップ](03-clinical/workflow.md) の順で整理する。

[全体の業務の流れ](domain-overview.md)、[相談・決定記録](discussion-log.md) も参照する。個別文書は相談に合わせて追加する。

## 文書の扱い

- 一覧を対象範囲と候補名の入口とする。確定した要望、モデル案、未決事項を区別する。
- 制度条件は一次資料・該当箇所・適用日を確認する。
- 実装方式と共通IDの配置は業務上の責任を整理してから決める。
