# 用語・履歴と領域間の受け渡し

## 用語

組織・基盤コンテキストにおけるユビキタス言語を以下のとおり定義する。

| 用語 | 定義 | 区別・境界の原則 |
| --- | --- | --- |
| 法人 (`Corporation`) | 薬局の開設・管理の基本単位（区分：`法人` / `個人`）。個人開設者や店舗を開設しない持株会社等もモデル上は法人として統一的に扱う | 個人区分では13桁法人番号を持たない（同一開設者・役員兼任・実質支配等がある場合の法人間関係登録は可） |
| 企業グループ | 複数法人のまとまりを説明する呼称。独立したグループID・所属・階層は設けない | 報酬上の同一グループ判定結果（`GroupAssessment`）とは別概念 |
| 法人間関係 (`CorporateRelation`) | 法人間の `親子（支配）`（最大1親）・`関連会社`・`FC・VC契約` と期間・根拠メモ | 報酬上の同一グループ判定に関わらない業務提携は対象外。関係があっても別テナントであり、認可とは分離する |
| 開設者 (`Operator`) | 薬局の開設主体となる法人（区分：`法人` / `個人`） | 店舗との開設関係は半開区間で管理する（運営担当の分離は想定しない） |
| 店舗 (`PharmacyStore`) | 業務上継続して扱う薬局の単位（併設の店舗販売業許可等も紐づけ可） | 物理拠点、許可、保険薬局指定とは別に識別する |
| 物理拠点 (`StoreLocation`) | 住所・区画・緯度経度・設備等の場所 | 移転時は別の物理拠点として登録し利用期間を切り替える |
| 報酬上の同一グループ (`GroupAssessment`) | 制度版・基準日・対象期間に基づき法人間関係から導出する判定結果 | 親子関係そのものとは別の、施設基準上の評価結果 |
| 管理主体 | 品質・インシデント案件を管理する発生店舗の開設者（法人） | 親法人へ自動委任しない。詳細は [品質・インシデント](../05-pharmaceutical-care/quality.md) を参照 |
| スタッフ (`Staff`) | テナント内で業務に従事する人物（派遣・業務委託も自法人との契約区分で表現） | ログイン主体（アカウント）と必ず1対1対応としつつ概念として区別する |
| テナント (`Tenant`) | 法人ごとのデータ分離境界。1法人＝1テナント | 企業グループはテナントではない |
| アカウント (`Account`) | システムにログインする主体（テナントごとに別。スタッフと必ず1対1） | 店舗配属とアクセス権限付与（RBAC）は完全に別操作とする |

## 正本の所有領域と参照先

| 情報 | 正本を持つ領域 | 主な参照先 |
| --- | --- | --- |
| 法人（法人/個人区分）・法人間関係（親子/関連会社/FC・VC） | 法人 (`corporate`) | 店舗、施設基準（報酬グループ判定）、テナント・アクセス管理 |
| 店舗・物理拠点・営業日時・連絡先・開設者関係・許可・保険指定 | 店舗 (`store`) | 処方箋、調剤、在宅、施設基準、算定、保険請求 |
| 人物・所属契約・店舗配属・資格・勤務・管理薬剤師就任 | スタッフ (`staff`) | 監査・調剤・指導・薬歴確定の実施者、施設基準 |
| 基準の評価・届出・適用情報・報酬上のグループ判定 (`GroupAssessment`) | 施設基準 (`facility_compliance`) | 算定、店舗運営 |
| ヒヤリハット・インシデントの報告・調査・是正・効果確認 | 品質 (`quality`：`05-pharmaceutical-care`) | 店舗（起票・実施報告）、法人（案件管理）、調剤等の業務記録 |
| 法人の利用設定・アカウント・RBAC権限・監査ログ・データ移行 | テナント・アクセス管理 (`tenant_access`) | 全領域の利用認可 |

## 共通の履歴管理ルール

- **半開区間**: 業務上の有効期間はすべて `[valid_from, valid_to)` で表現する。日単位の事実には日付を用い、切替日 `D` では旧関係の終了と新関係の開始をともに `D` とする。
- **バイテンポラル管理**: 実際の発生・効力日（有効期間）と、システムに入力・訂正した日時（記録日時）を分離する。
- **参照整合性の保全**: 関係の終了や法人の合併消滅・店舗閉店はレコード削除を意味しない。過去の業務記録が指す主体とその実施時点のスナップショットを不変に保持する。
- **状態の分離**: 予定と確定実績、申請（届出）と適用確認、人事配属とアクセス権限を厳格に区別する。

## 領域をまたぐ組織変更時の連動

| 変更イベント | 各領域での処理内容 |
| --- | --- |
| 企業の株式買収 | 法人間関係（`CorporateRelation`）を更新し、施設基準の `GroupAssessment` を再確認。店舗・権限・テナントは変更しない |
| 店舗の事業譲渡 | 店舗の開設者関係切替、許可・保険指定（`predecessor_id` 保持）の登録、新法人でのスタッフ登録、施設基準再届出、承認されたデータ承継・認可を個別実行 |
| スタッフの異動・応援 | 店舗配属・勤務予定を変更し、管理薬剤師就任、施設基準の常勤換算、RBAC権限付与・失効をそれぞれ更新 |
| 店舗の閉店 | 営業状態を `閉店` へ更新し、届出終了、権限見直し、返戻・再請求対応、法定保存期間中の参照維持を管理 |

組織変更を束ねる独立した案件オブジェクトは設けず、法人、法人間関係、店舗の開設者、スタッフの所属・配属等がそれぞれ変更前後・有効期間・変更者・記録日時・根拠を履歴として保持する。
