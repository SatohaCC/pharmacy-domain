# 組織と薬局の全体構造

薬局の物理実体・法人実体・許認可・保険指定・スタッフを単一のオブジェクトに混在させず、**変更単位と法的意味ごとに集約を分離**して管理する。詳細な仕様は [組織・基盤](README.md) 配下の各文書で定義する。

## 中核エンティティと分離原則

| 概念 | ドメイン上の意味 | 分離・設計の原則 |
| --- | --- | --- |
| 法人 (`Corporation` / `Operator`) | 薬局の法的な開設・管理主体（区分：`法人` / `個人`）。1法人＝1テナント | 店舗を開設しない持株会社や個人開設者も同一モデルで扱い、個人区分は法人番号を持たない |
| 法人間関係 (`CorporateRelation`) | 法人間の `親子（支配）`（最大1親）・`関連会社`・`FC・VC契約` と有効期間 | 固定のグループIDを持たず、基準日時点の関係グラフから報酬算定上の同一グループを導出する |
| 店舗 (`PharmacyStore`) | 薬局業務を継続して行う事業上の単位 | 物理拠点、薬局開設許可、保険薬局指定コードとは独立したIDで識別する |
| 物理拠点 (`StoreLocation`) | 住所・区画・緯度経度・プライバシー配慮設備等の場所 | 移転時は新拠点を登録して利用期間を切り替え、過去記録の所在地参照を維持する |
| 許可 (`FacilityLicense`) | 薬局開設許可・麻薬小売業免許・店舗販売業許可等の行政許可 | 1店舗に複数紐づけ可能。麻薬小売業免許の有効期限切れ・未登録時は麻薬調剤をブロックする |
| 保険薬局指定 (`InsuranceDesignation`) | 都道府県コード2桁・点数表区分1桁・機関コード7桁、指定日、適用期間、`predecessor_id` | M&A・移転時の遡及指定および旧債権分離のため、承継元指定IDの系譜を保持する |
| スタッフ (`Staff`) | テナント内で業務に従事する人物（アカウントと必ず1対1） | 店舗配属・勤務実績・管理薬剤師就任と、システム上のアクセス権限（RBAC）を完全分離する |

## 構造上の不変条件

- **資本・契約関係とデータ閲覧境界の分離**: 法人間関係（親子・関連・FC/VC）は報酬上の同一グループ判定の材料としてのみ用い、別テナントの薬歴・患者情報の閲覧権限を自動付与しない。
- **期間管理の統一**: 店舗と開設者の関係、拠点の利用期間、許認可・指定の適用期間、スタッフの配属・就任期間はすべて半開区間 `[valid_from, valid_to)` で履歴管理する。
- **調剤実施日時点のスナップショット復元**: 組織変更や移転が起きた後でも、過去の調剤実施日時点における「開設者・管理薬剤師・保険薬局コード・有効施設基準」をセットで復元できる構造とする。

## 対応する組織変更シナリオ

1. **単独開設・複数店舗運営**: 1つの法人が単一または複数の店舗を開設し、スタッフの主配属・応援勤務と店舗別アクセス権限を管理する。
2. **企業グループ・FC展開**: 親会社・子会社・関連会社・FC/VC加盟法人がそれぞれ独立テナントとして運営しつつ、法人間関係グラフから同一グループ判定（`GroupAssessment`）を行う。
3. **株式譲渡（買収）**: 開設法人ID・テナント・店舗ID・許可・保険薬局コードを維持したまま、法人間関係（親子関係）の履歴のみを更新する。
4. **事業譲渡・法人成り**: 店舗の開設者を切替日 `D` で旧法人から新法人へ切り替え、許認可・保険指定の更新と承認されたデータ承継を実行する（譲渡前のレセプト・調剤実績に対する新法人の遡及修正は禁止）。
5. **吸収合併・店舗移転**: 消滅法人の主体履歴や移転前の物理拠点履歴を保持し、過去の業務記録および返戻・監査参照の整合性を維持する。
