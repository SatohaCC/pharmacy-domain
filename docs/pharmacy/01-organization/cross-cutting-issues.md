# 共通の詳細論点

状態: 相談用のモデル案（マルチテナント対応）。制度に依存する判断は、根拠と適用時点を確認してから確定する。

基本モデルは [企業・企業グループ](corporate.md) と [店舗](store.md) に分けて整理する。本書は、企業・店舗にまたがる承継・制度・期間等の共通論点を検討する補足資料。用語は [用語・履歴と領域間の受け渡し](organization-contracts.md#用語) に合わせる。テナント・認可・移行の基本は [テナント・アクセス管理](tenant-access.md) を正本とし、本書では承継との関係だけを扱う。

## 対象範囲

薬局システムで管理する企業、企業グループ、開設者、企業間関係、店舗、許可・指定と、M&A等による変更を整理する。経営計画・人事制度・財務会計の詳細は対象に含めない。

## 管理する概念

| 概念 | 表したいこと | 設計上のポイント |
| --- | --- | --- |
| 企業 (`Corporation`) | 法人（区分：`法人` / `個人`）。店舗を開設しない持株会社等や個人開設者も含む |
| 法人間の関係 | `親子（支配）`（最大1親）・`関連会社`・`FC契約`、期間、根拠メモ | 各法人は別テナント。手動登録で法人グループおよび報酬上の同一グループ判定材料を表現。独立したグループID・階層は設けない |
| 企業間関係 (`CorporateRelation`) | `親子（支配）` / `関連会社` / `FC契約` と適用期間 | 方向、根拠メモ（議決権比率・支配力・契約等）、確認状態を保持。個人区分は対象外 |
| 開設者 (`Operator`) | 開設主体となる法人（法人/個人区分） | 実務の運営担当との分離は想定しない |
| 屋号・ブランド (`Brand`) | 店舗が使用する名称・ブランド | 法人と1対1にせず、店舗への適用期間を持つ |
| 薬局店舗 (`PharmacyStore`) | 業務上継続して扱う店舗 | 場所そのものとは区別。同一IDの維持は運用上の判断に委ねる |
| 物理拠点 (`StoreLocation`) | 住所・区画・緯度経度等の場所 | 移転時は別拠点を登録し、店舗との利用期間を管理。同じ場所への再出店を自動的に同じ店舗にしない |
| 店舗と開設者の関係 (`StoreOperatorAssignment`) | 店舗の開設主体（法人）と期間 | 当時の主体を参照できる履歴を保持 |
| 許可 (`FacilityLicense`) | 許可種別、名義人、発行者（許可権者）、対象施設、番号、有効期間 | 1つの店舗に薬局開設許可と店舗販売業許可等の複数を紐づけ可能 |
| 保険指定 (`InsuranceDesignation`) | 指定を受けた開設者、対象薬局、都道府県コード(2桁)・点数表区分(1桁)・機関コード(7桁)、指定日、適用期間 | 旧指定との系譜を保持。系譜は実績合算・閲覧許可の根拠そのものではない |
| データ承継 (`DataSuccession`) | 対象記録、当事者、根拠、利用目的、承認、結果 | 指定の承継系譜やテナント所属から独立して管理。テナント移行は [テナント・アクセス管理](tenant-access.md) で扱う |

## 店舗の同一性

移転で `StoreLocationId` は変わる。`PharmacyStoreId` を維持するかは運用上の判断（担当者が継続か新規かを選ぶ）に委ねる。事業譲渡でも同様に運用上の判断で継続性を決める。

許可・指定・コードの維持、新設、変更はこの判断とは独立して確認する。指定の系譜は、複数の承継元・承継先を表せる関係として検討する。

## 期間と履歴

- 有効期間は半開区間 `[valid_from, valid_to)` に統一する。終了未定は `valid_to` なしとする。
- 組織所属等の日単位の事実には日付を使い、切替日Dでは旧関係の終了と新関係の開始をともにDとする。
- 時刻が必要な勤務・就任等にはタイムゾーンを明示した日時を使う。日付の情報を推測で秒単位へ変換しない。
- 有効になった時点と、システムに登録・訂正した時点を区別する。遡及指定や後日の訂正でも当時の登録内容を追跡する。
- 過去記録の参照先を保ち、訂正は履歴付きで行う。保存期間は「保存と訂正」で記録種別ごとに決める。

## 報酬上の同一グループ

報酬算定上の同一グループ判定を対象とする。法人間関係（`CorporateRelation`：`親子（支配）` / `関連会社` / `FC契約`）を判定材料とし、制度上の定義（最終親会社等、子会社等、関連会社等、FC契約）に沿って評価する。

企業グループ（呼称）と報酬上の判定結果を区別する。法人間関係を判定材料とし、適用制度の版、基準日、集計対象期間、起点、対象法人・薬局、根拠経路、確認状態を持つ `GroupAssessment` を設ける。判定結果の正本は [施設基準・届出](facility-compliance.md) で保持し、算定領域へ渡す。

### 判定の手順案

1. 対象法人から支配関係を上向きに調べ、最終親会社等の候補を得る。
2. 対象が関連会社・FC加盟側の場合も、その関連元・契約先から起点候補を得る。関係の向きと役割を明示し、関連先同士を無制限に再帰結合しない。
3. 起点候補ごとに、適用制度が指定する子会社等・関連会社等・FC先の範囲を評価する。関連会社の子会社等を含めるかなどの探索範囲は制度の版ごとに定義する。
4. 対象法人が含まれる判定結果を返す。複数候補、根拠不足、関係の矛盾があれば要確認とし、一つへ黙って統合しない。自動算定への利用は確認後とする。

支配関係は循環を検出する。単一親制約は、採用する支配関係の定義を確認してから導入する。関連関係・FC関係は複数候補を扱えるようにする。連結財務諸表等による取扱いは、対象制度・資料・適用期間を記録して判定する。

制度改定時に確認する一次資料の入口は [厚生労働省の診療報酬改定情報](https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/0000106602.html)。具体的な通知・該当箇所・適用日が確認されるまでは、本手順を制度適合済みのアルゴリズムとは扱わない。

## 管理薬剤師等の就任との接続

許可の切替と、実際の管理対象施設・就任・勤務の関係を分ける。同じ施設で同じ人物が継続する場合、許可世代が変わっただけで実際の兼務が生じたとは判定しない。

複数施設の期間重複は確認対象として検出し、役割・施設種別・業務内容・適用規定・許可された例外等により判断する。根拠は [薬機法](https://laws.e-gov.go.jp/law/335AC0000000145) と関連規定の適用箇所を確認して追加する。

## 変更のケース

独立した組織変更案件は設けず、以下の変更は各情報の履歴で追跡する。データ承継・移行の根拠と実行結果は、アクセス管理側の記録として保持する。

| ケース | 維持・変更の案 | 確認・承認が必要なこと |
| --- | --- | --- |
| 法人AがX・Yを開設 | 企業、店舗、拠点、開設者関係、許可・指定を登録 | 記録が実施時点の主体・指定を指すこと |
| BがAを株式取得、Aが開設を継続 | Aと店舗のIDは維持する案。企業間関係を更新。テナントは維持し、必要な移行は別途確認 | 許可等の変更要否を個別確認。グループ判定日と算定への反映時期を分離し、買収日から即時合算とは断定しない |
| AからBへXの事業を譲渡 | 店舗継続の判断を記録。開設者関係を切替。必要な許可・指定の変更を確認結果に従い登録 | Xの承継対象記録、利用目的、権限、保存担当、譲渡前後の請求・債権の取扱い。指定系譜から閲覧を許可しない |
| AがBへ吸収合併 | Aの識別・履歴と消滅日を保持。開設者関係を変更 | 許可・指定等の手続、返戻対応、保存責任、閲覧権限を各領域で確認・記録。包括承継と全職員への閲覧許可を混同しない |
| 法人間の承継・移行 | 法人＝テナントを前提に、組織変更の効力日とシステム移行日を分け、それぞれの履歴を記録 | [テナント・アクセス管理](tenant-access.md) の移行手順に従い承認する |

許可・指定の新設・変更の要否は、M&Aの種別から自動決定しない。遡及指定の施行日・類型を含め、適用する一次資料と管轄機関の確認結果を該当する許可・指定の履歴に記録する。

## データ承継と閲覧権限

事業承継に伴う提供や承継後の利用目的については [個人情報保護委員会の通則ガイドライン](https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/) を参照する。承継の条件を満たすかと、特定職員へ閲覧を許可するかは別に評価する。

- 株式取得や同じグループへの所属だけでは、親会社・他法人への薬歴閲覧を許可しない。
- 同じ法人（テナント）内でも、職務、店舗、目的、患者・記録の範囲に基づいて認可する。
- データ承継の記録は、対象記録の集合、提供元・承継先、利用目的、根拠、適用日、承認者を持つ。店舗共通の患者マスタや複数店舗の記録を一括移行しないよう分割条件を確認する。
- Xの事業のみを承継した場合、Yの記録は承継スコープに含めない。A側の既存アクセスは、保存・請求等の必要性に基づき別途決める。双方からの一律遮断とはしない。
- 臨床記録、請求記録、債権を分け、原記録の主体・実施時点と、現在の管理・対応責任者を保持する。
- 事業譲渡前のレセプト・調剤実績は譲渡元（旧法人）の請求・調剤責任に属するため、譲渡先（新法人）側からの遡及変更・修正請求は禁止（スナップショット参照のみ）とする。
- 薬歴の承継は法令および患者同意に基づき行い、引き継いだ場合も当時の記載者・責任法人の履歴を保持する。
- 特定共同指導等やレセプト電算出力（CZ/KI）に備え、**調剤実施日時点における「開設者・管理薬剤師・保険薬局コード・届出施設基準」をセットで復元・適用できること**を横断要件とする。
- 交渉段階の提供は、本番の承継とは別の承認と契約条件で扱う。交渉不成立時の返還・消去等も記録する。

承継に伴うテナント移行と、別テナント間の報酬集計は [テナント・アクセス管理](tenant-access.md) で扱う。グループ判定を理由に他テナントの患者情報を直接参照しない。

## 保存と訂正

| 記録種別 | 確定すること |
| --- | --- |
| 調剤録 | 根拠規定、保存期間、起算点、保存責任者 |
| 調剤済み処方箋・電子処方箋関連記録 | 媒体・制度ごとの対象、保存期間、起算点、責任者 |
| 薬歴・薬学的管理記録 | 対象記録、算定等の根拠、保存期間、起算点 |
| レセプト・会計・債権記録 | 請求・税務等の根拠、保存期間、承継後の対応主体 |
| 移行・アクセス監査記録 | 保存目的、期間、閲覧範囲 |

各記録は法令・制度が定める保存期間（3年・5年等）を下回らないよう記録種別ごとの保存ポリシーで保持し、具体的な年数表は実装・制度マスタ側へ委ねる。係争等の保全条件や承継後の担当も記録する。訂正は原内容と経緯を追跡できる形で行い、原則として物理削除は行わない。匿名化・廃棄等は保存方針と承認に従う。

## モデルを確認する例

- 親子（支配）・関連会社・FC契約の履歴をもとに、最終親会社等・関連元・FC本部等の起点候補から同一グループを評価する（根拠不足や矛盾があれば要確認）。
- 複数グループ候補があれば要確認となり、自動統合しない。
- 切替日Dの旧期間にはDを含めず、新期間にはDを含める。
- 移転時に拠点は変わり、店舗継続の判断が記録される。
- 指定の承継系譜だけでは薬歴閲覧を許可しない。
- テナント移行後も原記録の主体・作成時所属・変更履歴を参照できる。
