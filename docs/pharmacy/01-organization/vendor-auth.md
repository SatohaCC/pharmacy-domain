# システムベンダー認証・アカウント管理

## 基本方針とドメイン境界

- **薬局テナントとの分離**: 薬局側利用者（`Corporation` ＝ 1法人1テナント、`Account` ⇔ `Staff` の1対1対応）とは独立したプラットフォーム運用主体コンテキスト（`vendor_auth` / `VendorUser`）として管理する。
- **初期管理者のコンソール発行**: システムベンダーの最初の管理アカウント（`admin`）は、Web 上の公開サインアップを設けず、コンソール CLI（`python -B -m app.cli.bootstrap_vendor_admin`）のみから発行する。既にベンダーユーザーが存在する場合、コンソールからの初期管理者再発行は拒否する。
- **Web での社員発行**: 初期管理者発行後のベンダー社員アカウント（`admin` / `member`）は、ログイン済みの `admin` のみが Web 管理画面（`/vendor/users`）および `POST /api/vendor/users` から発行する。

## 管理する概念とモデル

| 概念 | 主な情報 | ルール・制約 |
| --- | --- | --- |
| ベンダーユーザー (`VendorUser`) | ユーザーID、メールアドレス（小文字正規化・一意）、表示名、ロール（`admin` / `member`）、状態（`active` / `disabled`）、パスワードハッシュ、作成者ID | メールアドレスをログイン識別子とし、一意とする。`disabled` ユーザーはログイン・トークン更新・API 実行を許可しない |
| リフレッシュセッション (`RefreshSession`) | セッションID（`jti`）、ファミリーID（`family_id`）、対象ユーザーID、リフレッシュトークン SHA-256 ハッシュ、発行日時、有効期限、ローテーション日時、失効日時、置換先セッションID | 発行から **480 分** を有効期限とし、ローテーションおよび再利用検知によるファミリー単位失効を行う |

## 認証・セッション・パスワード要件

- **パスワード要件**: 医療情報システムの安全管理に関するガイドライン（第7.0版・二要素認証未導入時）に準拠し、**13 文字以上 128 文字以下**、制御文字・前後空白禁止、英大文字・英小文字・数字・記号のうち **3 種類以上** の混在を必須とする。Web 発行時は管理者が初期パスワードを設定し、安全なパスワードの自動生成ボタンを補助として提供する。
- **JWT トークン（HS256）**:
  - **アクセストークン**: 有効期限 **30 分（1800 秒）**、HttpOnly Cookie `vendor_access_token`（`Path=/api`, `SameSite=Lax`, `Max-Age=1800`）で送信する。
  - **リフレッシュトークン**: 有効期限 **480 分（28800 秒）**、HttpOnly Cookie `vendor_refresh_token`（`Path=/api/vendor/auth`, `SameSite=Lax`, `Max-Age=28800`）で送信する。
- **ローテーションと再利用検知**: `POST /api/vendor/auth/refresh` 実行時は新しいセッションID・リフレッシュトークン・アクセストークンを発行して旧セッションを置換する。すでにローテーション済みまたは失効済みのリフレッシュトークンが再利用された場合は、同一 `family_id` の全セッションを即時失効させる。
- **ログアウト即時失効**: `POST /api/vendor/auth/logout` 実行時は DB 上の該当セッションファミリーを即時失効させ、ブラウザ側 Cookie を削除する。
- **CSRF 対策**: Cookie 認証を伴う状態変更 API では、許可された `Origin` / `Referer` 検証または `X-Requested-With: XMLHttpRequest` ヘッダを必須とする。
